# 文章分类、标签筛选、搜索与极简写作模板

Status: ready-for-agent

## Problem Statement

作为 Hr00 博客的作者，我已经积累了普通文章和 Weekly，但普通文章目前几乎都使用含义模糊的 `Share` 分类，没有一致的标签，也没有一个可以按主题浏览文章的入口。读者只能按首页时间线或全文搜索寻找内容，无法快速查看某一类文章、组合多个感兴趣的标签，或者从文章详情继续浏览相关内容。

现有写作模板还预置了大量章节、占位正文和写作问题。它们虽然试图帮助组织文章，却增加了开始写作前的清理成本，并容易让文章迁就模板结构。现有 `poem` 空值回退、搜索字段、分类数据和遗留的 `hidden` / `hide` 行为也不一致，容易造成页面表现和内容发现行为不符合作者预期。

## Solution

为普通文章建立清晰而克制的内容组织体系：每篇文章只属于一个固定分类，并可以拥有零至五个开放标签。新增统一的文章索引页面，让读者通过单分类和多标签组合筛选文章；在文章详情中显示可点击的分类和标签；扩展现有全站搜索，使分类和标签命中具有更高优先级，同时继续搜索 Weekly。

顶部导航中的 GitHub 入口替换为文章入口，其他位置的 GitHub 个人链接保持不变。筛选在一个静态生成的文章索引页面中完成，并通过 URL 保存状态，不引入数据库、后端或独立分类/标签页面。

写作流程改为四份与固定分类一一对应的极简模板。模板只保留 Front Matter，正文完全留空；发布构建负责校验标题、摘要、分类和标签。`poem` 保持可选，空值自动回退到文章标题。现有文章一次性迁移到新内容模型，遗留的 `hidden` / `hide` 能力被移除。

## Implementation Decisions

- 普通文章使用“单一分类 + 多标签”内容模型。每篇文章必须拥有一个分类，并允许零至五个标签。
- 固定分类为：技术实践、学习笔记、生活记录、思考随笔。分类是受控列表，不能在文章中自由创建。
- 标签是开放列表。同一概念只有一个标准写法；比较时忽略首尾空格和大小写差异，展示时保留标准写法并优先使用官方名称。
- 普通文章使用单数分类字段和复数标签数组。分类值直接使用中文，不维护内部英文标识到中文名称的额外映射。
- Weekly 不使用普通文章的分类或标签，但继续参与全站搜索。
- 顶部导航中的 GitHub 项替换为“文章”，目标为 `/articles/`。About、页脚、作者元数据和 SEO 中的 GitHub 链接保持不变。
- `/articles/` 是唯一的文章索引入口。分类与标签不生成独立永久页面，也不引入归档插件、数据库、后端 API 或第三方搜索服务。
- 文章索引由 Jekyll 在构建期输出全部可发现文章及其元数据；客户端 JavaScript 只负责增强筛选交互。无 JavaScript 时仍显示完整的已发布文章列表。
- 文章索引展示文章总数、“全部”与四个固定分类、分类数量、全部已用标签、标签数量、当前筛选、结果数量、清除筛选和文章结果列表。
- 分类最多单选一个，标签允许多选。标签之间使用 OR；分类与标签集合之间使用 AND。
- 文章索引结果按发布时间倒序排列。零结果时显示明确空状态，不回退到无筛选结果。
- 筛选状态使用 URL query parameters 表达。`category` 表示单一分类，`tags` 表示多个标签；刷新、复制 URL、浏览器前进和后退必须恢复相同状态。
- 分类与标签控件使用统一大小的可操作按钮，不使用按频率改变字号的标签云。布局需要在桌面与移动端都可读、可点选并清楚显示选中状态。
- 文章索引列表沿用博客现有的简洁视觉语言，并补充分类与标签信息。
- 文章详情页显示唯一分类和全部标签。分类和标签都可点击，并跳转到带有对应筛选状态的文章索引。
- 全站搜索索引增加标签数据，并保留标题、摘要、正文、分类、日期、类型和 Weekly 数据。
- 搜索从简单布尔过滤升级为相关性排序。标题、分类和标签命中属于最高优先级，摘要次之，正文命中最低；相同相关性下保持稳定且可预测的排序。
- Weekly 继续按标题、描述和正文参与搜索，并保持 Weekly 类型标识；它不伪造普通文章分类或标签。
- 搜索结果展示文章分类，并在有助于识别结果时展示标签；标签和分类内容必须安全转义，不能将 Front Matter 文本直接作为可执行 HTML。
- 新写作模板共四份，名称与四个固定分类一一对应。每份只包含 Front Matter，正文完全留空，四份模板仅在预填分类上不同。
- 每份模板保留布局、标题、`poem`、摘要、分享封面、分类、标签和发布状态。标题、`poem`、摘要和分享封面初始为空，标签初始为空数组，`published` 初始为 `false`。
- 文章日期由符合约定的 Markdown 文件名提供；新模板不重复提供日期字段。
- `poem` 是可选页头短句。只有非空时才覆盖标题；缺失或空字符串时必须回退到文章标题。
- 删除遗留的通用模板，避免与四份分类模板并存。执行删除前需要确保 MiaoYan 没有继续打开该文件，防止编辑器缓存将其重新创建。
- 发布校验只约束准备发布的普通文章；草稿允许标题、摘要和正文未完成。
- 发布文章必须具有非空标题和摘要、且分类属于固定列表。标签必须是数组、最多五个、同篇不得重复，也不得通过大小写或首尾空格制造重复。
- 校验错误必须包含文章标识、出错字段和可执行的修正说明。错误阻止生产构建，不静默修正分类或截断标签。
- 移除 `hidden` / `hide` 的首页排除逻辑和所有相关特殊处理。普通文章只通过草稿状态决定是否发布和参与站内发现。
- 现有七篇文章全部迁移到“技术实践”。标签依次为：Kaku AI 终端使用 Kaku 与 Terminal；妙言使用指南使用 Markdown 与写作；GitHub Desktop 使用使用 Git；Hr00 开发使用博客；终端编辑快捷键使用 Terminal 与快捷键；Mac 使用 macOS 与工具推荐；Terminal-Tools 使用 Terminal。
- 现有英文 `Share`、`Study`、`Learn`、`Thought` 分类不再作为普通文章分类继续使用。
- 迁移与实现必须保留用户当前工作区中的并行配置和草稿改动，只修改功能所需的精确内容，不进行全量暂存或无关清理。

## Testing Decisions

- 主测试 seam 是 production-equivalent Jekyll build：使用与生产一致的构建入口生成站点，通过生成后的 HTTP 页面和 JSON 数据验证外部行为，而不是测试 Liquid 分支、DOM 私有函数或内部变量。
- 在成功构建上进行黑盒浏览器验证：确认顶部“文章”入口、文章索引初始状态、分类单选、标签多选、标签 OR、分类与标签 AND、结果数量、清除筛选、空状态和时间倒序。
- 浏览器测试覆盖直接打开带 query parameters 的 URL、刷新、复制后重新打开、前进和后退，确认筛选状态与可见文章一致。
- 浏览器测试从文章详情点击分类和标签，确认跳转到文章索引并应用正确筛选。
- 搜索测试使用构建生成的真实搜索数据，通过公共搜索交互验证标题、分类、标签、摘要和正文命中，以及高优先级字段排在正文偶然命中之前。
- 搜索测试确认 Weekly 仍可被找到，并且不被错误展示为普通文章分类。
- 响应式黑盒检查至少覆盖一个桌面宽度和一个移动端宽度，确认筛选按钮可读、可点击、可换行，结果列表无水平溢出。
- 无 JavaScript 检查确认构建后的文章索引 HTML 已包含完整可发现文章列表，而不是依赖客户端获取后才出现内容。
- Front Matter 校验通过真实 Jekyll 构建执行。测试 fixture 覆盖：有效发布文章、允许不完整的草稿、空标题、空摘要、未知分类、非数组标签、超过五个标签、同篇重复标签和仅大小写不同的重复标签。
- `poem` 行为通过构建输出验证：非空值显示 `poem`，空字符串和缺失字段都回退到标题。
- 迁移测试确认七篇现有文章具有约定分类与标签，并且旧英文分类不再出现在文章索引或普通文章搜索元数据中。
- 回归检查确认 About、页脚和结构化作者信息中的 GitHub 链接仍存在，只有顶部导航入口被替换。
- 回归检查确认遗留 `hidden` / `hide` 条件不再改变文章发现行为。
- 现有测试先例是生产 Jekyll 构建和零依赖 Ruby 行为测试。新增自动测试应优先复用这些轻量入口；只有浏览器外部行为无法被构建产物断言覆盖时才引入最小浏览器测试层。
- 完成条件包括：自动校验通过、生产构建成功、生成数据断言通过、桌面与移动端浏览器流程通过，并且没有修改或暂存无关工作区内容。

## Out of Scope

- 为 Weekly 添加分类、标签或与普通文章共用筛选。
- 为每个分类或标签生成独立永久页面、Feed 或 sitemap 落地页。
- 多分类文章、层级分类、父子标签或标签颜色管理。
- 数据库、CMS、后台管理界面、登录、编辑 API 或第三方托管搜索。
- AI 自动分类、AI 自动标签、标签推荐、同义词自动识别或标签合并工具。
- 将文章索引筛选控件放入当前首页时间线。
- 重做博客整体导航、视觉主题、文章排版或 Weekly 页面。
- 移除 About、页脚、作者元数据或 SEO 中的 GitHub 链接。
- 私密文章、密码保护文章或“仅链接访问”的 `hidden` / `hide` 模式。
- 将标签硬限制为每篇一至两个；全局上限仍为五个，现有文章只是主动使用精简标签。
- 发布到生产环境、提交、推送或创建 Pull Request；这些动作需要在实现完成后单独确认。

## Further Notes

- 仓库当前是单一 Jekyll 内容上下文，领域词汇表已经定义文章、Weekly、分类、标签及四个固定分类。本 spec 使用这些名称，不把分类称为栏目，也不把标签称为分类或搜索关键词。
- 当前文章详情已经读取 Jekyll 归一化后的分类集合，搜索数据也已有分类字段；实现可以在现有构建数据和搜索入口上扩展，不需要另建内容数据库。
- 当前 `poem` 判断只检查字段是否存在；Liquid 会把空字符串视为真值，因此必须显式排除空字符串才能实现标题回退。
- MiaoYan 是 Markdown 编辑入口，不提供动态 Front Matter 表单。四份分类模板是降低手工填写分类成本的主要方式。

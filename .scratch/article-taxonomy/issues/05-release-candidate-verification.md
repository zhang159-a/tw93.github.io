# 05 — 验证完整的文章发现流程

**What to build:** 将分类写作、文章索引、多标签筛选和全站搜索作为一条完整用户路径进行生产等价验证，修复只在组合后出现的回归，并提供足够证据说明功能可以进入后续提交或发布阶段。

**Blocked by:** 03 — 增加多标签组合筛选; 04 — 按分类和标签改进全站搜索.

**Status:** ready-for-agent

- [ ] 使用仓库约定的 Ruby 与生产构建入口完成一次干净的 production-equivalent build。
- [ ] 从顶部导航进入文章索引，完成全部文章、单分类、多标签、分类与标签组合、清除和空状态的桌面端流程。
- [ ] 在移动端宽度完成相同核心流程，确认控件可读、可点选、可换行且没有水平溢出。
- [ ] 直接打开筛选 URL、刷新、复制后重新打开以及浏览器前进和后退，结果与 URL 状态始终一致。
- [ ] 从文章详情点击分类和标签能够到达正确筛选状态。
- [ ] 禁用 JavaScript 后文章索引仍显示完整已发布普通文章列表。
- [ ] 全站搜索验证标题、分类、标签、摘要、正文的相关性顺序，并确认 Weekly 仍可被找到。
- [ ] 旧英文分类和 `hidden` / `hide` 特殊发现行为不再出现在最终构建结果中。
- [ ] About、页脚、作者元数据和 SEO 中的 GitHub 链接保持不变，只有顶部导航入口被替换。
- [ ] 自动测试、生成数据断言和浏览器黑盒检查全部通过，并记录具体命令与结果。
- [ ] 检查最终 diff 和工作区状态，确认 Dia 草稿、并行配置、其他草稿及无关文件没有被修改、删除或纳入交付。
- [ ] 不执行提交、推送、Pull Request 或生产部署；这些动作等待用户单独授权。

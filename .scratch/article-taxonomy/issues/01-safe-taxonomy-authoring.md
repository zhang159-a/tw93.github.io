# 01 — 建立安全的分类写作流程

**What to build:** 让作者可以从与四个固定分类一一对应的极简空白模板开始写作，并让真实生产构建在发布前验证文章的分类、标签和必要元数据。迁移 spec 中已确认的七篇文章，修正可选页头短句的回退行为，并移除遗留的 `hidden` / `hide` 特殊状态。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 提供技术实践、学习笔记、生活记录、思考随笔四份模板；模板只包含约定的 Front Matter，正文完全留空。
- [ ] 四份模板预填各自唯一分类，并保留空标题、空 `poem`、空摘要、空分享封面、空标签数组和 `published: false`。
- [ ] 模板不重复提供日期字段，遗留通用模板被安全移除且不会因 MiaoYan 缓存重新进入交付内容。
- [ ] 不完整草稿可以通过生产构建；准备发布的文章必须具有非空标题、非空摘要和四个固定分类之一。
- [ ] 发布文章的标签必须是数组、最多五个，同篇文章不能包含重复、仅大小写不同或仅首尾空格不同的标签。
- [ ] 校验失败会阻止生产构建，并明确指出文章、字段和可执行的修正方式；构建不会静默改写分类或截断标签。
- [ ] `poem` 缺失或为空字符串时页头显示文章标题，非空时显示 `poem`。
- [ ] spec 指定的七篇文章全部迁移到技术实践，并使用已确认的精简标签和官方大小写；旧英文分类不再保留在这些文章中。
- [ ] `hidden` / `hide` 不再改变普通文章的发现行为，文章只通过发布状态区分草稿和已发布内容。
- [ ] 新增的 Dia 草稿和所有未纳入 spec 的并行内容保持原样，不替作者推断分类或标签。
- [ ] 真实生产构建和针对有效、草稿及各类无效 Front Matter 的自动测试全部通过。
